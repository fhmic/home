# FM Finance Suite — fhmic/home

Personal site and finance-suite web apps for **Felix Happy Michael (Elites)** —
chartered accountant and financial strategist. Single repo, public, served by
GitHub Pages at **fhmic.github.io/home**.

Frontend is static HTML/CSS/JS (no framework, no build step to *write* code —
only to ship it, see [Build & deploy](#build--deploy-pipeline) below). Backend
is a separate Node.js/Express/MongoDB API on Render
(`eis-recbackend.onrender.com`) that every app below calls over REST.

## Point-in-time ("As-Of") reporting

Treasury and Receivables can report the business position **as at any past
date**, not just live/today:

- Every balance update (cash, borrowings, investments, equity) is saved with
  an **effective date**, not overwritten — so history accumulates from real
  data entry, not a guess.
- A one-time **baseline "Data Effective From" date**, set once in Treasury →
  Settings, is the earliest date reports can be pulled for. Nothing before it
  can be reliably reconstructed, so the app blocks it rather than guessing.
- The dashboard's **As-Of date picker** reconstructs the full position — per
  entity, the latest dated value on or before the chosen date — and every
  export (PPT / PDF / Excel) is labelled and filed by that same date, not
  today's date.
- Nothing in the underlying figures auto-accrues interest day to day —
  outstanding/principal only change when a dated update is posted. A small,
  clearly-labelled **estimated accrual** overlay (`rate × days since last
  posted figure`, Actual/365) is shown alongside the posted balance so drift
  between updates is visible without being mistaken for a confirmed figure.

## Repository structure

```
src/            Real, editable HTML/CSS/JS. Edit here.
docs/           Generated by build.js. Committed (so Pages can serve it),
                but auto-refreshed by CI — don't hand-edit.
build.js        The obfuscation/build pipeline (src/ → docs/).
package.json    Build-only dependencies (clean-css, javascript-obfuscator).
.github/workflows/build.yml
                On every push to main touching src/, build.js, or
                package.json: installs deps, runs `npm run build`, commits
                the refreshed docs/ back to main. Nothing to run locally,
                no secrets/tokens needed.
```

## One-time GitHub Pages setup

Settings → Pages → Source: **Deploy from a branch** → Branch: **main**,
folder: **/docs**.

## Day to day

Edit files under `src/` (the web UI is fine for this). Commit to `main`. CI
rebuilds `docs/` within about a minute and the live site updates.

## Build & deploy pipeline

Each page's `<body>` markup is captured as a string and folded into that
page's JS bundle, then injected into a single empty `<div>` at runtime via
`.innerHTML` — the same technique SPA frameworks (React/Vite) use to keep
"view source" nearly empty. The shipped HTML shell for every page ends up in
the same ~15–25 line range as a Vite/React build's shell, instead of showing
the full page markup.

On top of that:
- JS is run through `javascript-obfuscator` (hex-renamed identifiers,
  control-flow flattening, base64-encoded string array) rather than just
  minified — sample output looks like `_0x17d4c2=...`, not readable code.
- CSS is minified via `clean-css`.
- All HTML comments are stripped from the shipped output.
- Every `onclick`/`onchange`/`oninput`/etc. attribute's target function name
  is auto-detected from the source and explicitly protected from renaming,
  so those handlers keep working exactly as before — verified by simulating
  every page in a headless DOM and confirming the injected markup renders
  and every handler name survives.

### Two honest limits, still true regardless of any of this

1. **This raises the bar, it doesn't make the code secret.** Anything that
   runs in a visitor's browser must be sent to that browser in full,
   plain-text, parseable form — obfuscation makes it unpleasant to read, not
   impossible to eventually reverse. The only real way to keep logic truly
   secret is to move it server-side (the Express backend) and have the
   frontend just call an endpoint.
2. **This repo is public**, so `src/` (the readable version) is still
   browsable on github.com itself, even though it's never what ships to the
   live site's visitors. If that needs to be hidden too, the repo itself
   needs to be private (which has its own tradeoffs).

## Backend

Node.js / Express / MongoDB, deployed separately on Render at
`eis-recbackend.onrender.com/api`. Auth is per-user with per-module
view/edit permissions (`requirePermission` / `requireModuleAccess`), and data
is scoped either by `namespace` (org-wide, used by Treasury) or `ownerId`
(per-user, used by Receivables) — not part of this repo, deployed and
versioned independently.

## Tech stack

- **Frontend:** vanilla HTML/CSS/JS, Chart.js, SheetJS (xlsx), jsPDF +
  html2canvas, PptxGenJS — no framework, no bundler for authoring.
- **Build:** Node.js, `javascript-obfuscator`, `clean-css`.
- **Backend:** Node.js, Express, MongoDB (Mongoose), deployed on Render.
- **Hosting:** GitHub Pages, served from `/docs` on `main`.
